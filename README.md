# m3u8-probe

本地开发用的**网页 m3u8 调试录制器**。它驱动你本机的 Edge / Chrome，录下真实的网络请求，
找出页面到底在取哪个 playlist，并把 HLS 结构解析出来。

不是解析器猜测，也不是正则扫 HTML：它看的是浏览器真的发出去的请求。

## 为什么需要它

自己的站点上视频播不出来，或者你根本不知道播放器的流地址从哪来——
`.m3u8` 可能写在 JS 里、可能由接口返回、可能地址里根本没有 `.m3u8`。
打开这个工具，操作到视频出画面，它把三条线索都摆给你。

## 判定有三条腿

| 腿 | 依据 |
| --- | --- |
| `url` | 地址里含 `.m3u8` |
| `mime` | 响应 `Content-Type` 是 mpegurl |
| `body` | 响应体以 `#EXTM3U` 开头 |

第三条腿受 CDP 限制：页面 `fetch` 之后**没有读过**的响应体取不回来。
工具不会假装解析成功——拿不到体时会直接复取这个地址，
复取成功且体像 m3u8 就照样记入，详情里如实标注「复取」来源。

## 范围

这是"**你自己驱动的浏览器**"的调试录制器。

- 起始地址随你填：本地页面、你要调试的任何单页站点都行。
- 不做批量抓取，不接受 URL 清单，一次只录一个页面。
- 始终使用独立临时 profile，不读取你日常浏览器的登录数据。
- 会话 Cookie、请求头和原始响应体不会进入事件流、导出文件或 Pages。

## 用法

需要 Node.js ≥ 22.4（内置 `WebSocket` 从 22.4 起默认可用，`fetch` 更早）。**没有 npm 依赖。**

### 双击直开（不装任何东西）

直接双击 `ui/index.html`。页面会自动改用 `ui/bundle.js`（由 `node tools/bundle.mjs`
从同一份模块源码生成的经典脚本——file:// 下浏览器不让加载 ES module），
演示模式照常能玩；要取你自己站点的真实地址，用下面任一方式跑起来。

### 网页控制台（真录制）

```bash
node bridge.mjs
```

打开它给出的地址（默认 <http://127.0.0.1:8787/>）：

1. 填起始 URL（你要调试的页面），按需调整端口、浏览器、嗅探、自动收尾。
2. 点**开始录制**，会弹出一个独立 profile 的浏览器窗口。
3. 在那个窗口里操作到视频真的开始播放，命中会实时出现。
4. 点**停止并出报告**。

控制台里可以搜索（地址、发起者、codec、密钥地址）、按判定腿 / 类型 / 加密 / 直播筛选、
按码率或分片数排序、拖动排序、批量选择、保存视图、导出 JSON / CSV / 地址清单。
删除和清空都可以撤销。

### 命令行

```bash
node m3u8-probe.mjs http://localhost:3000/ --open
```

在浏览器里操作到视频播放，然后 `Ctrl-C` 收尾。`--help` 看全部选项。

## 下载到文件（N_m3u8DL-CLI）

拿到地址只是第一步：控制台整合了 [N_m3u8DL-CLI](https://github.com/nilaoda/N_m3u8DL-CLI)，
界面上每条地址（地址输出区、命中卡片、详情抽屉）都有**下载**按钮，
进度、阶段（下载 → 合并）和最终文件位置显示在左侧「下载」面板。

1. 把 `N_m3u8DL-CLI.exe` 放进项目根目录、`tools/`、PATH，或在「下载」配置里填完整路径。
   自动探测按这个顺序找；合并成 mp4 还需要 ffmpeg 在它同目录或 PATH 里。
2. 保存目录默认是项目下的 `downloads\`，可在「下载」配置里改；请求头（Referer / Cookie）
   也在这里填，会原样传给 CLI 的 `--headers`。
3. 一次下载一个地址，由你亲手点出来；多个下载可以并行，和录制互不影响。

成败判定看文件不看退出码（CLI 异常被 catch 后照样 Exit 0）：任务结束但
`<saveName>.*` 没出现就是失败。直播流不支持自动下载（CLI 在无人值守下会挂起），
面板会明确报错。

## GitHub Pages 上是演示模式

Pages 只有静态文件，没有本地桥接，所以线上版本用一份**按当前配置生成的示例录制**驱动：
所有控件照常可用，但不会真的启动浏览器。点**随机示例**换一批。

这是有意的：桥接不开 CORS，远端页面读不到你 localhost 上的录制数据。
要录任何站点，就在本地跑 `node bridge.mjs`，把页面地址填进去。

部署：把 `ui/` 作为 Pages 产物即可，`.github/workflows/pages.yml` 已经配好，
推送到 `main` 就会自动开启 Pages 并发布。

## 测试

```bash
npm test
```

包含 playlist 解析、CDP 边界、桥接 HTTP/SSE、下载器（输出解析 / 下载 REST+SSE / 假 CLI 全链路）、
前端 store 与导出，以及会真的启动浏览器的端到端用例——这部分需要本机装有 Edge 或 Chrome，没有就会失败。

## 已知边界

- 只解析 HLS。DASH 的 `.mpd` 会作为"媒体线索"列出来，但不解析。
- 复取失败时只报状态码，不猜原因（403 可能是 Referer、签名或 Cookie，工具不替你断言）。
- Windows 上无法给子进程送 `Ctrl-C`，所以桥接用 stdin 写一行 `stop` 来优雅收尾。
- 下载整合的 N_m3u8DL-CLI 是 Windows 上的 .NET Framework 4.6.1 程序；
  Node 侧只负责拉起进程和解析它的输出（进度行按行切，编码不通用时进度仍可读），
  阶段串匹配的是 zh-CN 资源原文，其它 locale 下进度条仍工作、阶段徽章会缺失。
