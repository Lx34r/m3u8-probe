# m3u8-probe

本地开发用的**网页 m3u8 调试录制器**。它驱动你本机的 Edge / Chrome，录下真实的网络请求，
找出页面到底在取哪个 playlist，并把 HLS 结构解析出来。

不是解析器猜测，也不是正则扫 HTML：它看的是浏览器真的发出去的请求。

## 为什么需要它

自己的站点上视频播不出来，或者你根本不知道播放器的流地址从哪来——
`.m3u8` 可能写在 JS 里、可能由接口返回、可能地址里根本没有 `.m3u8`。
打开这个工具，操作到视频出画面，它把三条线索都摆给你。

## 判定有三条腿

| 腿 | 依据 |
| --- | --- |
| `url` | 地址里含 `.m3u8` |
| `mime` | 响应 `Content-Type` 是 mpegurl |
| `body` | 响应体以 `#EXTM3U` 开头 |

第三条腿受 CDP 限制：页面 `fetch` 之后**没有读过**的响应体取不回来。
这种情况只能靠前两条腿，工具会在详情里说明复取结果，不会假装解析成功。

## 范围

这是"**你自己驱动的浏览器 + localhost**"的录制器。

- 起始地址只接受 `localhost` / `127.0.0.1` / `[::1]`，桥接和前端都会拒绝其它地址。
- 不做批量抓取，不接受 URL 清单，不面向第三方站点。
- 始终使用独立临时 profile，不读取你日常浏览器的登录数据。
- 会话 Cookie、请求头和原始响应体不会进入事件流、导出文件或 Pages。

## 用法

需要 Node.js ≥ 22（用到内置的 `WebSocket` / `fetch`）。**没有 npm 依赖。**

### 网页控制台（推荐）

```bash
node bridge.mjs
```

打开它给出的地址（默认 <http://127.0.0.1:8787/>）：

1. 填起始 URL（你自己的本地站点），按需调整端口、浏览器、嗅探、自动收尾。
2. 点**开始录制**，会弹出一个独立 profile 的浏览器窗口。
3. 在那个窗口里操作到视频真的开始播放，命中会实时出现。
4. 点**停止并出报告**。

控制台里可以搜索（地址、发起者、codec、密钥地址）、按判定腿 / 类型 / 加密 / 直播筛选、
按码率或分片数排序、拖动排序、批量选择、保存视图、导出 JSON / CSV / 地址清单。
删除和清空都可以撤销。

### 命令行

```bash
node m3u8-probe.mjs http://localhost:3000/ --open
```

在浏览器里操作到视频播放，然后 `Ctrl-C` 收尾。`--help` 看全部选项。

## GitHub Pages 上是演示模式

Pages 只有静态文件，没有本地桥接，所以线上版本用一份**按当前配置生成的示例录制**驱动：
所有控件照常可用，但不会真的启动浏览器。点**随机示例**换一批。

这是有意的：桥接不开 CORS，远端页面读不到你 localhost 上的录制数据。
要录你自己的站点，就在本地跑 `node bridge.mjs`。

部署：把 `ui/` 作为 Pages 产物即可，`.github/workflows/pages.yml` 已经配好，
推送到 `main` 就会发布（先在仓库 Settings → Pages 里把 Source 设为 GitHub Actions）。

## 测试

```bash
npm test
```

包含 playlist 解析、CDP 边界、桥接 HTTP/SSE、前端 store 与导出，
以及会真的启动浏览器的端到端用例——这部分需要本机装有 Edge 或 Chrome，没有就会失败。

## 已知边界

- 只解析 HLS。DASH 的 `.mpd` 会作为"媒体线索"列出来，但不解析。
- 复取失败时只报状态码，不猜原因（403 可能是 Referer、签名或 Cookie，工具不替你断言）。
- Windows 上无法给子进程送 `Ctrl-C`，所以桥接用 stdin 写一行 `stop` 来优雅收尾。
